1. How it works

A deck is one Markdown file plus a media folder:

my-deck/
  deck.md      the presentation
  media/       images referenced as media/x.png

Open the folder in the presentation player. No build step is needed.

Slides are 1280×720. They do not scroll or shrink to fit; overflowing content is clipped.

Use Markdown and the HTML components below. Reuse the supplied layouts and styles rather than adding one-off CSS.

2. The editing loop

Edit deck.md, save, and inspect the result. Folder previews reload Markdown and media changes while preserving the selected slide.

Use one header and one content block per slide. These are the maximum counts that fit:

Component Ceiling on one slide
Cards in a row 4
Feature-list items 4
Stats 3
People 7
Timeline milestones 5
Trailing .overline Only if it fits on one line

Put supporting detail in Note:. Speaker notes are hidden on slides and in the PDF.

3. Previewing a slide

The author presents it

Chrome or Edge: open /present/, click Open folder, pick the folder. Arrow keys navigate, Esc opens the slide overview, and M opens the menu. Choose Fullscreen from the menu. S toggles speaker notes. Edits to deck.md reload live.

Safari or any other browser: zip the folder (zip -r deck.zip deck.md media) and load the zip from the same page. A zip is a snapshot, with no live reload. A single .md also loads, with no media.

PDF: choose Menu → Export PDF, then Print / Save PDF in the new tab. In the print dialog set Destination: Save as PDF, Layout: Landscape, Margins: None, and Background graphics: on. With that off, every filled card and dark slide prints white. PDF export reopens a saved folder. Open the deck as a folder before exporting.

Use 16:9 paper with background graphics enabled. Choose a custom size of 13.333 × 7.5 in. A4 adds white bands; keep the deck at 1280×720.

Working across separate filesystems

If your agent cannot write to the folder open in the presenter’s browser:

  1. Deliver deck.md and its media/ folder.
  2. The presenter opens that folder once in Chrome or Edge and leaves the tab open.
  3. Return updated Markdown and any changed media. The presenter replaces those files in the same folder.

Edits in an agent’s sandbox do not update the presenter’s local files.

Render and inspect local slides as an agent

Use the slide renderer with a browser tool that can attach files and capture screenshots. No website checkout or local server is needed.

  1. Package deck.md and its media: zip -r deck.zip deck.md media/.
  2. Open https://www.eigin.ai/present/render/?slide=1 in a 1280×720 browser viewport.
  3. Supply the ZIP to the file input labelled Choose a presentation file. A standalone Markdown file works for decks without local media. Files are read in the browser and never uploaded to the website.
  4. Wait for the top-level body’s data-render-status to become ready or error. On error, read the visible alert and fix the deck. On ready, capture a screenshot and inspect it.
  5. Read data-total-slides. Repeat with ?slide=N and the same file bytes to inspect other slides.
  6. Edit your local files, rebuild the ZIP, and supply the updated bytes through the same input. Wait for ready and inspect a fresh screenshot.

Example using an existing Playwright page. The only file it reads is your deck ZIP: 

import { readFile } from 'node:fs/promises';

const bytes = await readFile('deck.zip');
await page.setViewportSize({ width: 1280, height: 720 });
await page.goto('https://www.eigin.ai/present/render/?slide=1');
await page.waitForFunction(() => document.body.dataset.renderStatus === 'idle');
await page.getByLabel('Choose a presentation file').setInputFiles({
  name: 'deck.zip',
  mimeType: 'application/zip',
  buffer: bytes,
});
await page.waitForFunction(() =>
  ['ready', 'error'].includes(document.body.dataset.renderStatus)
);
if (await page.locator('body').getAttribute('data-render-status') === 'error') {
  throw new Error(await page.getByRole('alert').innerText());
}
const total = Number(await page.locator('body').getAttribute('data-total-slides'));
await page.screenshot({ path: 'slide-1.png' });

Passing file bytes works when the browser runs on a different machine from the agent. For a browser tool with its own file-attachment command, target the same labelled input. The input remains available to automation after the slides replace the launcher.

Signal Meaning
data-render-status="idle" Waiting for a local file.
data-render-status="loading" Reading or rendering the deck.
data-render-status="ready" The selected slide and its fonts/images are ready to capture.
data-render-status="error" Read the alert; fix the content or missing media, then supply the file again.
data-total-slides Total slides in flat order, including vertical slides.
data-current-slide Selected slide, counted from 1.

?slide=N selects a 1-based slide and clamps to the available range. Omit it to navigate with arrow keys. Local files are snapshots: reattach updated files after edits. Wait for readiness rather than a fixed delay. The browser needs network access to load the public website.

Existing URL-based renderer integrations

The agent route also accepts ?src= for Markdown and ?zip= for ZIP files on a CORS-enabled server. These parameters are optional. Source URLs watch by default without a selected slide; watch=0 disables watching and watch=1 enables it. ZIPs are snapshots.

4. Slide syntax

You write You get
--- on its own line A new slide (blank line before and after)
---- on its own line A vertical sub-slide, reached with the down arrow
Note: at the end of a slide A speaker note, hidden from the audience
<!-- .slide: class="…" --> Classes on the slide itself

Use a vertical stack when several slides share one composition and only the content changes, so pressing down reads as the same picture evolving: a run of quotes, or a product walk-through.

5. The header and alignment

Two things the system decides for you, so you do not decide them per slide.

The header

An h1 followed by <p class="subhead"> is the standard head on every content slide. The subhead tucks under the title and opens a wider gap before the content. Write the two in sequence and it works. 

# The premise

<p class="subhead">Personal AI will become essential infrastructure.</p>

Vertical alignment follows the content

Content Alignment
Text: prose, quotes, lists, paragraphs Top — reading starts at the same height every time
A lone figure: diagram, timeline, grid of cards Centred under the header — a figure has no reading entry point
layout-statement, layout-title, layout-center Centred on the slide
Two or more stacked blocks Top, flowing

A figure only auto-centres when it is the sole content block (last child, directly after the header). Put anything after it and the slide reverts to top. Override with .fill on a child or spread on the slide.

6. Layouts and modifiers

Put on the slide: <!-- .slide: class="layout-… theme-…" -->

Layout Use for
(none) Standard content: header plus text or components. Top and left aligned.
layout-cover Cover slide. Write the content and the panel builds itself, see below.
layout-title Opening slide: centred kicker + big title + lede.
layout-statement One big centred statement, nothing competing.
layout-statement lg The headline becomes the slide: a few short stacked lines over full-bleed art. For pivot moments only.
layout-hero Product walk-through: one device screenshot at full slide height with a short headline beside it.
layout-center Centre the content vertically and horizontally.

Recommended title slide: website-style cover

For a branded opening, use a full olive background with the bird at the upper right. Keep the logo and title at the lower left, followed by a two-line introduction and a presenter line. This composition leaves the centre open and gives the title room.

Copy this complete example into deck.md. The bird and logo are supplied by the website renderer, so no media files are needed. Replace the introduction and presenter line. The 120px title is intended for a short name such as Eigin; use a smaller title size or the simpler cover below for longer headings. Render and inspect the result before presenting.

This is an intentional custom cover. Keep its styles scoped to .website-cover and leave them unchanged when editing the copy. no-mark removes the normal corner mark because the title already includes the logo. Use the supplied CSS mask for the logo: currentColor matches the title colour, and 1cap matches its capital-letter height. The wordmark’s text-box trim aligns the visible lettering with the mark. Keep both spans; replacing the mask with an image or fixed pixel size loses this matching.

A simpler cover without custom CSS

For a quick cover without custom styles, write a headline and, optionally, a date and a subtitle. The player sorts them into the olive panel and the meta column for you. 

<!-- .slide: class="layout-cover" data-art="mountain" -->

# The headline goes here

<p class="subhead">An optional line under it.</p>

<p class="kicker">01.01.2026</p>
<p class="muted">Pitch deck</p>

The headline, .subhead and .lede go in the panel. Everything else, typically .kicker and .muted, goes in the meta column on the right. data-art is optional and takes any illustration name (see below), cropped by the panel edge behind the headline. Leave it off for a plain olive panel.

Do not hand-build .cover-panel and .cover-meta unless you want a composition this does not give you. A hand-built cover is left alone, so both work, but the short version is the one that is hard to get wrong.

Use layout-cover for slide one, not layout-title. layout-title is a plain centred title with no panel and no art. It is fine for a section break, but it is not the branded cover and it will look like a placeholder next to the rest of the deck.

Modifiers: theme-light (dark is the default) · text-left (keep a statement or cover left-aligned) · no-mark (hide the corner logo) · spread (first block top, last block bottom).

Region splits divide the area under the header. Cells align to the top, so a header inside a split cell lands on the usual baseline.

Class Columns
split Half / half
split thirds-right Third / two thirds — text beside big media
split thirds-left Two thirds / third — list beside a small aside
split wide-left / wide-right Weighted halves
columns Equal flex columns, any number

Every slide carries the Eigin logo bottom-right automatically, in the right colour for its theme. Never add one.

Light and dark

Slides are dark by default. theme-light flips one to the light palette. Convention: dark for narrative and statements, light for evidence and data.

8. Content components

Cards — rounded, flat fills, never bordered

<div class="cards cols-2">          <!-- cols-1 … cols-4 -->
  <div class="card olive">
    <span class="card-label">Optional label</span>
    <h3 class="card-title">Sentence-case title</h3>
    <p class="card-body">Body copy.</p>
  </div>
</div>

Colours: olive, warm, soft, coral, peach, rose, pink, deep, impact (dark). One accent per slide is plenty.

Add visual to .cards for tall cards that stretch to fill the slide, with a large icon on top and text pushed to the bottom. Use it when two or three cards would otherwise float in empty space. Wrap the text in a <div> so it groups. tall does the same stretch without an icon. 

<div class="cards cols-3 visual">
  <div class="card olive">
    <span class="shape" style="--shape:url(/assets/icons/illustration/butterfly.svg)"></span>
    <div>
      <h3 class="card-title">Personal AI agents</h3>
      <p class="card-body">Fastest growing category in consumer tech.</p>
    </div>
  </div>
</div>
Two rows of visual cards will overflow. Each one is full content height, so the variant is for a single row. For a 2×2 grid use plain cards cols-2.

Feature list — the primitive that replaces a wall of text

<div class="feature-list marked">   <!-- also cols-2 / cols-3 -->
  <div class="feature">
    <h4 class="feature-title">Local-first</h4>
    <p class="feature-desc">Everything stays on your device.</p>
  </div>
</div>

marked hangs an olive arrow beside each title. Use it when the list is the argument; leave it off when the list is supporting detail. features is the same idea with an icon above each title instead.

Numbered steps

<div class="numbered">
  <div class="step">
    <span class="step-n">1</span>
    <div>
      <h4 class="step-title">Title</h4>
      <p class="step-desc">Description.</p>

</div>

Stats — a number can replace a paragraph

<div class="stat-row">
  <div class="stat">
    <span class="stat-number">6</span>
    <span class="stat-label">enterprise sales</span>
    <span class="stat-note">At 400k to 600k DKK each.</span>

</div>

People — one uniform team grid

<div class="people">

</div>

Everyone is the same size on the same column track; seniority is carried by the role text, not by scale. Rows align even when a name wraps.

Timeline — milestones on a rail

<div class="timeline">

9. Diagrams

Diagrams are built from themed HTML components, not a diagram language. They adapt to light and dark automatically.

Piece Markup
Node <div class="node"><span class="n-title">Label</span><span class="n-desc">detail</span></div> — variants primary, deep, accent
Group <div class="group"><span class="group-label">Your device</span> …nodes… </div>
Flow <div class="flow"> node <span class="arrow"></span> node </div> — arrow variants down, dashed
Column <div class="col">…</div>
Stack (layers) <div class="stack"><div class="layer">Apps</div><div class="layer muted">Cloud</div></div>
Pills <div class="pill-row"><span class="pill on">Local</span><span class="pill">Cloud</span></div>

Inline SVG, for anything the components cannot draw

Curved edges, funnels, charts and flywheels are inline <svg>. Use class="diagram-svg" on the <svg>, class="edge" on connector paths, and CSS variables for every colour so the drawing follows the theme: var(--eigin-primary), var(--dg-text), var(--dg-muted), var(--dg-line), var(--dg-surface), var(--dg-panel).

Match the viewBox aspect ratio to the space. The SVG fills the content width and the leftover height. If the viewBox is a different shape, the drawing is letterboxed inside it, so it renders small and floats with big margins. The content area under a header is roughly 1140×400, so a viewBox near 2.85:1 fills it.

Text in a diagram is set in the heading face by default, which is right for labels. For running sentences, wrap them in a .body-copy group to get the serif body face: 

<g class="body-copy" font-size="16" fill="var(--dg-muted)">
  <text x="0" y="336">SVG text does not wrap, so break</text>
  <text x="0" y="359">lines yourself with one text per line.</text>
</g>

A font-family attribute on the element will not work here, and neither will an inherited style on the group: the theme sets the font on text directly, and a CSS rule beats both.

10. Icons, art and colour

Need a new icon? Choose it from MingCute on Iconify. A website contributor adds its SVG to design/assets/icons/functional/, retains the licence attribution, and runs just generate web. After review and website deployment it becomes available to both the website and slides, and appears automatically in the catalogue. A deck-only agent should request the addition; editing a deck does not change the shared design system.

Slides use the same generated icons and illustrations as the website. Browse the current design-system asset catalogue for previews and exact /assets/design-icons/… paths. The catalogue and renderer are built from the same registry, so each website release keeps them in sync. Legacy /assets/icons/… paths remain supported for existing decks. Masks inherit the text colour; images preserve the artwork’s colours.

Primitive What it is
<span class="shape brand" style="--shape:url(…)"> A masked mark. Sizes sm / lg, or --shape-scale for fine correction. Colours brand / coral.
<span class="icon" style="--shape:url(…)"> Inline functional mark that inherits the text colour.
<span class="avatar" style="--shape:url(…)"> An olive circle with an inset illustration, where a portrait would go. ink inverts it.
<div class="bleed …"> Oversized art cropped by the slide edge, behind the content.
<div class="wash coral"> A full-bleed colour field for the slide.
On a filled card use a plain .shape; on a white card use .shape brand. The mark inherits font size, so a stray rule elsewhere on the page can shrink it. If two icons on one row look different sizes, suspect the CSS before you blame the glyph.

Bleed

Do not reach for this unless you can see the slide. A bleed is meant to be oversized art cropped by the slide edge. At the default size it usually lands fully inside the frame instead, where it reads as a sticker floating behind the text rather than as a composition. Getting it right means adjusting size and offsets while looking at the result, often several times. If you are working blind, leave it off: a clean slide beats a badly placed illustration. For art on a cover, use data-art (above), which is already positioned.

If you can see the slide, the rule of thumb is that the shape should be large enough to run off at least one edge, typically --size of 80% or more with a negative offset, and its colour has to sit against the panel or slide behind it. Pink on olive, for instance, fights. 

<div class="bleed top-left pink"
     style="--size:32%; --shape:url(/assets/icons/illustration/person-1.svg)"></div>

Positions: left, right, top-left, top-right, bottom-left, bottom-right. Colours: brand, pink, coral, rose, ink. flip mirrors it. For a hard crop, drive it directly: style="--size:124%; left:-12%; top:-54%". --size and left are percentages of slide width, top of slide height.

Use a <div>, never a <span>: Markdown wraps a bare inline element in a <p>, which breaks the positioning.

Wash, not background-color

<div class="wash coral"></div>. Colours: coral, pink, rose, peach, olive, deep, ink, or --wash. It sits under .bleed art, so a wash plus an ink bleed inverts the slide: coloured field, dark illustration.

Prefer a wash over data-background-color. Reveal paints that across the whole viewport, so the colour leaks into the letterbox around the slide and behind the controls. A wash stops at the slide edge.

Brand colours

Primary olive #A7B04E · deep green #42674A · secondary amber #FCAF53 · accent tan #B39779.

Illustrations available

bird (reserved for Eigin itself), butterfly, cactus, cell, circle, crab, flower, ghost, ink-1, ink-2, moon, mountain, octopus, person-1, person-2, root, snake, tree, volcano, wave.

The illustration/ marks are an organic decorative family and are not interchangeable with the icon sets. Use -fill icon variants beside brand/ icons and -line beside functional/ ones, and never mix fill and line on one slide.

11. Media

Put files in media/ and reference them relatively. Files outside the deck folder are not served and will 404. 

![Product screenshot](media/screenshot.png)
<img class="plain" src="media/logo.svg">      <!-- square corners -->

Media cell inside a split: <div class="split-media"><img src="media/x.png"></div>, plus oversize to let the image outgrow its column and crop at the slide edge.

Device screenshots and layout-hero

<!-- .slide: class="layout-hero no-mark" -->

<div class="split hero-split fill">
<div class="hero-copy">
<h1>Stay on top of life</h1>
<p class="lede">The life admin that eats your week.</p>
</div>
<div class="shot"><img src="media/app-04-day.png" alt="…"></div>
</div>
  • hero-split is a 30% / 1fr grid. .shot carries order:-1, so the device renders on the left while the headline stays first in the DOM for screen readers.
  • The h1 goes inside the column. This is the one sanctioned exception to the header rule: full-width caps the device at ~470px, in-column it gets ~613px. Only worth it when the screenshot is the argument.
  • fill hands the split the leftover height. Without it the device collapses.
  • Export device mockups on a transparent background and do not trim the transparent margin. The drop shadow extends below the device, so the alpha bounding box is not centred on the phone. Crop to it and the phone sits visibly high on every slide.

12. What silently breaks a slide

None of these produce an error. Each one costs an hour the first time.

Trap What happens
A blank line inside a raw HTML block Ends the block. The rest leaks out as plain text.
Missing blank lines around --- The separator is not recognised and two slides merge into one.
Two style attributes on one element The second is dropped.
transform or translate on .bleed The PDF export prints the art as a solid black rectangle. Position with margin-top instead.
Content overflowing a hero slide in print Chrome's print rasteriser discards the entire page, text included. It comes out blank.
An oversized image .reveal img caps every image at max-height:68vh and rounds its corners. Overriding both is on you.
Assuming 720px of height .slide-frame uses padding: 7% 5.5%, and percentage padding resolves against width. Vertical padding is 7% of 1280 (~90px), so a content slide has ~540px of usable height.
A stretched child inside .fill .fill also sets align-content:center, which sizes a grid row to its content, so the child never sees the height.
Editing deck.md while it is open in an editor An editor buffer can silently revert your write. Re-read the file before editing and confirm the write landed.
Blind string replacement Curly versus straight apostrophes have failed matches silently. Use a tool that errors on a missed match.

13. Keeping a deck consistent

  • One header pattern on every content slide. Do not hand-place titles.
  • Dark for narrative and statements; light for evidence and data.
  • Bleed art on statement and cover slides only, and only when you can see the result. Use data-art on a cover instead. Shapes inside cards and features only.
  • Uppercase is for h1 and h2 only. Sub-headings and card titles stay sentence case.
  • Weight hierarchy: h1/h2 are Bold; every smaller header (h3/h4, card titles, feature titles, panel titles, subheads, table headers) is DemiBold. No other weights.
  • Let alignment be decided by content type. Reach for .fill only when the rule genuinely gets it wrong.
  • If you want a second exception to a rule, the answer is a documented layout, not a one-off inline style.

14. Writing the copy

Make the point

  • Clarity first. Use concrete nouns, active voice, and short sentences. Remove jargon and empty adjectives.
  • State what is true. Include relevant limits, costs, and trade-offs. Distinguish shipped features from plans; say what is unknown.
  • Write to a person. Use “you” and “your”. Explain the practical effect, without hype or corporate phrasing.
  • Make the title a claim. Give the audience the point of the slide rather than a topic label.

Keep it short

  • One line for a subhead; two or three lines per body item.
  • Keep items in a row similar in length and grammatical structure.
  • Put explanation and supporting facts in Note:.
  • State the point directly. Avoid “not X, but Y”, empty triads, repetitive lists, and hedging.
Instead of Write Rule
None of these ask you to take our word for it. Built so you do not have to trust us. State the claim directly.
This one scales without us in the room. We are not involved in running it. Prefer a plain operational fact to a quip.
We use request batching to obfuscate your IP. We aggregate requests so providers don't see your IP. Explain the effect in ordinary language.

Mechanics

  • Use sentence case. The theme uppercases h1 and h2; do not type titles in caps.
  • Use British spelling: organisation, licence as a noun.
  • No em-dashes or exclamation marks.
