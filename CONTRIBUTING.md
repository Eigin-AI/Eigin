# Contributing to Eigin

If you want to contribute towards a future where personal AI is private, secure, and yours - you're in the right place. 

Contributions of all kinds are welcome.

## Ways to contribute

- **Report a bug**: open a [bug report](https://code.eigin.ai/dev/eigin/-/issues/new?issuable_template=bug_report)
- **Suggest a feature**: open a [feature request](https://code.eigin.ai/dev/eigin/-/issues/new?issuable_template=feature_request)
- **Improve the docs**: fix errors, clarify explanations, fill gaps
- **Submit code**: fix a bug, implement a feature, improve test coverage

## Getting started

See the [README](README.md) for build setup and the available `just` commands. Run `just generate` after cloning.

## Reporting bugs

Before filing a bug, check for [existing issues](https://code.eigin.ai/dev/eigin/-/issues) to avoid duplicates. When ready, use the [bug report template](https://code.eigin.ai/dev/eigin/-/issues/new?issuable_template=bug_report).

For security vulnerabilities, see [SECURITY.md](SECURITY.md) - do not open a public issue.

## Suggesting features

Use the [feature request template](https://code.eigin.ai/dev/eigin/-/issues/new?issuable_template=feature_request). Focus on the problem you're trying to solve and why it fits Eigin's goals: local-first, private, and serving the individual user.

## Submitting changes

- Keep merge requests focused. One thing at a time
- Run `just format` and `just test` before opening an MR
- Write a clear description of what changed and why
- Tests are expected for new behaviour

## Code style

Style is enforced by the formatter - run `just format` and don't argue with it.

## Contributor agreement

Before we can merge contributions, we'll ask you to agree to a simple contributor agreement. The details are being finalised - we'll update this section when it's ready.

## Security

See [SECURITY.md](SECURITY.md) for how to report vulnerabilities responsibly.
